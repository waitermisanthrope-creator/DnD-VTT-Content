# Опциональные сборники для установленной Unity1.00.34

Подготовлена поставка через существующий живой `catalog/v3/index.json`.
Пересборка приложения не требуется. Каталог v4 и огромные одиночные пакеты
2.0.0 остаются экспериментальными; текущий клиент получает только совместимые
самостоятельные тома 1.1.0 с максимум 100 предметами в каждом.

| Серия | Предметов | Томов |
|---|---:|---:|
| Оружие | 1322 | 14 |
| Броня и одежда | 755 | 8 |
| Материалы для крафта | 521 | 6 |
| Расходники | 252 | 3 |
| Хлам | 441 | 5 |
| **Всего** | **3291** | **36** |

Дополнительно сохранены прежние опциональные 120 алхимических ингредиентов:
они не продублированы внутри томов материалов. Установив всё, пользователь
получит 3411 записей. Каталог содержит 224 записи всех типов.

Новая сотня содержит 20 видов оружия (фальката, кхопеш, эсток, нагината и др.),
20 предметов ремесленной/дорожной одежды, 20 видов ремесленного сырья,
20 походных расходников и 20 сюжетных находок. Это новые записи, помимо
ранее подготовленных вариантов материала/отделки/зачарования. Все новые
описания написаны для проекта; исторические игровые характеристики —
авторская homebrew-трактовка, а не обещание точной исторической симуляции.

## Как скачать

1. Настройки → Мастерская дополнений → «Обновить каталоги».
2. Открыть «Инвентарь» и нужную категорию; найти «Сборник: … — том NN/NN».
3. Нажать «Скачать и установить» для нужных томов. У томов нет зависимостей:
   можно установить любой отдельный том, без первого и без остальных.
4. Открыть инвентарь персонажа → «Справочник / Свой предмет» и добавить предмет.
   В текущей версии видны первые 25 результатов: используйте поиск по названию.
5. Удаление тома убирает его из справочника; ранее добавленные в персонажа
   предметы сохраняются как самостоятельные данные инвентаря.

Видимая новая запись каталога не скачивает пакет автоматически. Обновление
прежнего первого тома также запускается вручную. Первые тома сохраняют
пять старых package ID и все 188 старых item ID; прежние URL/байты сохранены.
Новые тома имеют ID `dnd.items.volumeNN.<категория>`, так что текущая мастерская
раскладывает их в правильные разделы инвентаря. Сопоставление всех новых
item ID с экспериментальным источником хранится в
`sources/workshop-volumes-1.1.0.json`. Эти опубликованные ID теперь стабильны:
будущая миграция крупных v4-паков должна учитывать это сопоставление.

## Работающие механики и границы

- Вес, описание, категория есть у каждого предмета.
- Экипировка оружия/брони использует уже имеющиеся обработчики клиента.
  Новую боевую автоматику и исправления слотов из черновика Unity этот JSON
  не устанавливает. Особые свойства разрешает мастер.
- Новые лечебные расходники с фиксированным лечением работают через
  поддерживаемую potency-формулу; величина проверена на старом движке.
- Обычные зелья с костями и остальные ручные расходники списываются кнопкой
  применения без ложного автоматического эффекта; описание явно требует
  учёта эффекта мастером. Броски лечения из Unity-черновика ещё не выпущены.
- Общие «Сердце животного/монстра/гуманоида» и другие части доступны как
  материалы. Новые aliases для связи общих частей со старыми специальными
  алхимическими профилями требуют будущего клиента; старый клиент их не
  исполняет. Видовые профили прежних ингредиентов и рецепты сохранены.
- Таблицы добычи, интерфейс разделки и рецепты новых видов сырья не добавлены.

## Проверки перед публикацией

`python3 tools/verify_workshop_volumes.py`: schema/hash/bytes/dependencies,
уникальность ID, старые ID, предел 100 предметов и отсутствие зависимостей.
`dotnet run --project tools/compatibility-tests/ContentCompatibility.csproj -- .`:
**1096 проверок PASS**, против неизменённого runtime исходной ветки
`e99d922aeab38dde49ba4268a1db8a895a4f053e`; установка каждого тома отдельно,
Android/Windows platform contracts, перезапуск, удаление, все расходники,
лечебные величины, экипировка и экспорт/импорт сохранения.
Это тесты чистого C# runtime, не физические Android/Windows GUI-тесты.

Публикация идёт в два шага: immutable payload → публичная проверка 36 URL →
активация каталога → повторная проверка публичного каталога/хешей.
Проверка доставки: `python3 tools/verify_workshop_volumes.py --public`.

## Проверенная публикация payload

36 immutable JSON опубликованы в Content `main`, коммит
`bf2804a`; все 36 фактических публичных raw URL скачаны повторно и совпали
с ожидаемыми SHA-256/bytes до активации каталога. Существующие payload 1.0.0
и каталоги v1/v2 сохранены. Запись живого каталога активируется следующим
коммитом; после этого публичный индекс проверяется отдельно.
