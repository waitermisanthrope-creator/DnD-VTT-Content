# AGENTS.md — контракт ИИ-разработчика дополнений DnD VTT

Это **репозиторий модов**, а не исходный Unity-клиент. Цель: помочь человеку самостоятельно создавать, тестировать, исправлять и публиковать **совместимые, безопасные дополнения**. Новичку обучай последовательно, на русском. Если он спрашивает «как здесь работать?», первым делом направь его в `docs/MOD_AUTHOR_GUIDE.md`, `docs/FILE_ATLAS.md` и покажи работающий пример.

## Сначала прочитай
- `README.md`, `docs/MOD_AUTHOR_GUIDE.md`, `docs/FILE_ATLAS.md`, `docs/PUBLISHING.md`.
- `schemas/catalog-entry-v1.schema.json`; полезная нагрузка `packages/demo.race.lanternfolk.json`, `packages/dnd.class.blood_hunter.json`, `packages/dnd.feat.alert.json`.
- `catalog/v3/index.json` — текущий **живой** каталог Unity; `v1/v2` исторические.
- При сомнении проверь актуальные Unity-обработчики в `waitermisanthrope-creator/DnD-VTT`, ветка `experiment/unity-vtt`: `unity/Assets/Vtt/Runtime/WorkshopStore.cs` и `LegacySessionPanel.ContentManager.cs`.

## Перед любым редактированием
1. Определи существующий ID/тип/файл, проверь каталог и смежные ресурсы. Не создавай дубль.
2. Меняй `packages/<id>.json`, затем **по точным опубликованным байтам** вычисляй `bytes` и `sha256`; затем обновляй `catalog/v3/index.json`. Не угадывай checksum. Кодировка UTF-8.
3. Новый релиз мода — новая `version`. Не ломай старые ID персонажей и сохранений. Не меняй версии исторических каталогов для обычного мода.
4. Следуй реальным C#-ограничениям. Поддерживаются декларативные JSON `race/class/feat/item/craft/map/model/environment/appearance` с ограничениями; нет произвольных JS/DLL/C# хуков. Нельзя обещать автоматическую работу 20 уровней нового класса.
5. Публичный каталог ≠ закрытый черновик: запись в `main/catalog/v3` будет видна всем. Для незавершённого содержания пользуйся веткой и явно объясняй, что обычный клиент читает только публичный `main`.
6. Если у ИИ действительно есть права записи, он может самостоятельно помогать с GitHub, предоставив путь, SHA коммита и тесты. Если нет — подготовь готовые файлы и обучи коммиту через браузер. Не требуй Codex/платного аккаунта.
7. Доверенные администраторы проекта могут работать и публиковать без согласования с владельцем. **Не вводи выдуманных ограничений доступа**; GitHub write является фактическим разрешением на запись, пользовательские бейджи в приложении не эквивалентны GitHub-правам.
8. Проверяй лицензию, права на публикацию и происхождение ассетов; никакого исполняемого пользовательского кода, паролей, приватных сохранений и крупных бинарников в этом реестре.
9. После работы кратко отчитайся: файлы, причины изменений, контрольные суммы, реальные проверки, тест в приложении, нерешённые ограничения. Не утверждай, что Android/Windows проверены, пока их никто не проверил.

## По запросу новичка
Не обрушивай тысячи файлов. Объясни систему `Content`/`Assets`/`Unity`; открой один пример нужного типа; начни с **маленькой** расы/черты; сопровождай человека при создании, проверке JSON, публикации и тестировании в мастерской.
